# Устройство проекта

В первой версии браузер получает HTML, CSS и JavaScript от FastAPI. Страница запрашивает `GET /studies`. Обработчик читает таблицу `research` из SQLite и возвращает массив `items`. Исследования упорядочены по времени создания от новых к старым, затем по ID. При недоступности БД API возвращает HTTP 503, а страница предлагает обновить список.

`api.py` создаёт приложение и открывает хранилище при старте. `storage.py` создаёт каталог и таблицу при первом запуске. В контейнере база лежит в `/var/lib/blindspot/blindspot.sqlite3` на отдельном томе. Поля первой версии — ID, время создания, этап и ревизия. Каждое чтение открывает своё соединение.

## Модули следующих этапов

| Модуль | Задача | Этап |
| --- | --- | --- |
| validation, adapters | Паспорт, входные файлы, сигнатура ONNX и пробный прогноз | 2 |
| domain, datasets, isolation | Состояния, разделение строк и доступ рабочих контейнеров к F1/F2 | 3 |
| worker, statistics | Исполнение опыта, ответы по ID и метрики | 4 |
| agents, controller | Предложение и уточнение гипотез, очередь, сроки и расход попыток | 5 |
| confirmation, statistics | Фиксация F3 и независимые решения F4 | 6 |
| web, export | Просмотр, печать O1, выдача O2/O3 и повтор | 7–8 |

Оркестратор будет единственным писателем БД. Поисковый и подтверждающий процессы получат разные монтирования. Эту границу проверяет этап 3. В первом образе запущен только контроллер.
