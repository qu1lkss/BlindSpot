# Устройство проекта

В первой версии браузер получает HTML, CSS и JavaScript от FastAPI. Страница запрашивает `GET /studies`. Обработчик читает таблицу `research` из SQLite и возвращает массив `items`. Исследования упорядочены по времени создания от новых к старым, затем по ID. При недоступности БД API возвращает HTTP 503, а страница предлагает обновить список.

`api.py` создаёт приложение и открывает хранилище при старте. `storage.py` создаёт каталог и таблицу при первом запуске. В контейнере база лежит в `/var/lib/blindspot/blindspot.sqlite3` на отдельном томе. Поля первой версии — ID, время создания, этап и ревизия. Каждое чтение открывает своё соединение.

## Проверка входов

Форма отправляет пять файлов одним multipart-запросом. Сервер сохраняет комплект в каталоге версии и выдаёт UUID черновика. Вторая команда проверяет JSON, таблицу и ONNX. Проверка выполняется в дочернем процессе с ограничением времени. В журнале команд SQLite хранятся ключ идемпотентности, параметры команды и ответ. Повтор с тем же ключом не увеличивает ревизию.

GET /studies/{id} возвращает состояние и сохранённый протокол проверки. Ошибки содержат поле и русское пояснение. Смена файла в форме сбрасывает результат проверки; повторная загрузка создаёт отдельную версию.

Дальнейшие этапы и границы доступа описаны в [плане](plan.md).
