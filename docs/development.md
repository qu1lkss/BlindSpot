# Разработка

## Запуск

Нужны Docker Engine с Linux-контейнерами и Docker Compose v2. Выполните команды из корня репозитория. Для первой сборки нужен доступ к Docker Hub и PyPI.

```sh
docker compose build
docker compose up -d --no-build --pull never --wait
```

Откройте [BlindSpot на этом компьютере](http://127.0.0.1:8765). Проверить список из терминала можно командой `curl -fsS http://127.0.0.1:8765/studies`. На чистой установке ответ — `{"items":[]}`. Если порт занят, задайте `BLINDSPOT_PORT` перед запуском и откройте этот порт в браузере.

```sh
docker compose logs controller
docker compose down
```

Обычная остановка сохраняет именованный том `studies`. При следующем запуске достаточно второй команды из блока запуска. Собранный образ содержит Python, зависимости и страницу с её стилями и скриптом. Compose публикует порт контроллера только на IPv4 loopback хоста.

## Проверки

Рабочая среда совпадает с образом из Dockerfile. Прямые зависимости перечислены в pyproject.toml, полный набор версий и SHA-256 дистрибутивов — в requirements.lock. После осознанного изменения зависимостей lock обновляется из корня командой:

```sh
uv pip compile pyproject.toml --no-header --python-version 3.13 --generate-hashes --output-file requirements.lock
```

Чтобы проверить работающее приложение, выполните:

```sh
docker compose exec -T controller python - < tests/integration/test_storage.py
python3 tests/e2e/check_http.py http://127.0.0.1:8765
```

Первая команда проверяет создание и повторное открытие SQLite во временной папке. Вторая обращается к опубликованному порту с хоста. Хостовому Python достаточно стандартной библиотеки. Для проверки в браузере откройте страницу и нажмите «Обновить». Текст пустого списка приходит на смену индикатору загрузки после ответа API.

Контекст сборки ограничен списком в .dockerignore. Архив заданий, локальные данные, секреты и результаты запусков исключены из Git. В репозиторий помещаются только согласованные демонстрационные материалы и протоколы.

Автономность собранного образа можно проверить с полностью отключённой сетью:

```sh
docker run --rm -i --pull never --network none blindspot-controller:0.1.0 python - < tests/e2e/check_offline.py
```

Для браузерной проверки на чистом томе нужны Chrome, Node.js и доступный модуль Playwright (при испытаниях — 1.62.1). Команда открывает страницу, проверяет пустой список и восстановление после ошибки чтения:

```sh
node tests/e2e/check_browser.cjs http://127.0.0.1:8765
```

## Загрузка исследования

Нажмите «Новое исследование», выберите ONNX, CSV или Parquet и три JSON-файла. Кнопка «Загрузить и проверить» сохраняет комплект и открывает протокол. Исправленные файлы можно загрузить отдельным комплектом. Описание полей приведено в [формате входов](inputs.md).

Клиенты API передают в POST заголовки Idempotency-Key и If-Match (целочисленная ревизия, при создании 0). POST /studies принимает multipart-поля model, data, passport, policy, methods. POST /studies/{id}/validate возвращает протокол, GET /studies/{id} открывает сохранённое состояние. Повтор ключа с другим содержимым или устаревшая ревизия дают HTTP 409.

## Подготовка и проверка выборок

После успешной проверки нажмите «Подготовить выборки». API принимает POST /studies/{id}/prepare с теми же заголовками команды и возвращает размеры F1/F2. На томе версии сохраняются исходные материалы, контрольные суммы, split.json с ID, протокол и манифест. Поиск получает только подкаталог prepared/search. Для временных данных граница проходит между различными моментами времени; для зависимых групп все строки группы остаются вместе.

На доверенном хосте Docker командой ниже можно запустить проверку доступа для конкретной версии. Введите UUID с экрана вместо UUID_ВЕРСИИ. Нужна поддержка volume-subpath (испытано на Engine 28.4). Работник использует образ контроллера по ID, собственный временный каталог, каталог индекса данной версии, ограничение памяти и один CPU.

```sh
python3 scripts/search_worker.py UUID_ВЕРСИИ
```
