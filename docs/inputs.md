# Материалы исследования

Форма создания исследования принимает пять файлов. В API им соответствуют части multipart `model`, `data`, `passport`, `policy` и `methods`. Полные синтетические комплекты находятся в [каталоге примеров](../examples/README.md).

| Материал | Файл внутри версии | Назначение |
|---|---|---|
| I1 | `model.onnx` | Классификатор с обученной предобработкой в графе ONNX |
| I2 | `data.csv` или `data.parquet` | От 1 000 до 100 000 размеченных строк и от 10 до 100 признаков |
| I3 | `passport.json` | Словарь полей, порядок признаков, классы, входы и выход модели, происхождение |
| C1 | `policy.json` | Метрики, пороги, бюджет, доля поиска и seed |
| C2 | `methods.json` | Версия и условия применения каждой методики |

## Таблица и паспорт

В CSV используется UTF-8, запятая как разделитель, первая запись содержит заголовки. Десятичный разделитель — точка. Пустая ячейка означает пропуск. Значение `""` в кавычках означает пустую строку. Пробелы и ведущие нули строк сохраняются. Например, значения `001`, `1` и ` 1` образуют три разных строковых ID. В Parquet типы задаёт физическая схема файла. Пустому значению соответствует Arrow null. Для обеих форм имена колонок должны совпадать со словарём полей.

В `columns` паспорта у каждого поля есть имя `name`, описание `description`, роль `role`, тип `type`, единица `unit`, точность `precision` и разрешение на пропуски `nullable`. Если понятия единицы или точности к полю неприменимы, укажите JSON null. Точность описывает число десятичных знаков при представлении. При проверке диапазона сравниваются исходные значения до округления.

| Роль | Объявление |
|---|---|
| `id` | Единственный уникальный идентификатор каждой строки. Поддерживаются `string` и `integer` |
| `target` | Единственный столбец правильного класса. В `classes` перечисляются все разрешённые метки того же типа |
| `feature` | Числовой, логический или категориальный признак. Для числового диапазона задаются включительные `min` и `max`, для категорий — `categories` |
| `group` | Идентификатор группы зависимых строк типа `string` или `integer` |
| `time` | Поле типа `datetime`. Требуется временная метка с часовым поясом |

Для строки используется `string`, для целого — `integer` (int64), для вещественного числа — `number` (float64), для логического признака — `boolean`. Явные NaN и бесконечности в таблице отклоняются. Числовые границы включительны. Для целочисленных идентификаторов, классов и категорий в CSV используйте каноническую десятичную запись. Для кодов с ведущими нулями укажите `string`. Даты поступают с явным смещением, например `2026-01-01T12:30:00+03:00`. Для разбиения они приводятся к UTC.

Пример описания изменяемого признака в паспорте

```json
{
  "name": "length_mm", "description": "Длина изделия", "role": "feature",
  "type": "number", "unit": "мм", "precision": 1,
  "min": 0, "max": 100, "nullable": true, "mutable": true,
  "label_condition": "Измерительная погрешность в пределах 0,1 мм сохраняет класс изделия."
}
```

Изменение признака разрешает только `mutable: true` вместе с текстом `label_condition`. По умолчанию `mutable` равен false. Поля ролей ID, класса, группы и времени всегда обязательны и неизменяемы. Значения `dependence` задают схему зависимости наблюдений.

| Значение | Дополнительные роли |
|---|---|
| `independent` | Нет |
| `grouped` | `group` |
| `temporal` | `time` |
| `grouped_temporal` | `group` и `time` |

Список `features` задаёт порядок всех признаков. В `inputs` каждому тензору соответствуют `name`, упорядоченный список `columns` и `type`. Последовательность колонок всех входов должна воспроизвести `features`. Допустимы типы тензоров `float32`, `float64`, `int32`, `int64`, `string`, `bool`. Числовой пропуск передаётся модели как IEEE NaN в вещественном тензоре. В `output` задаётся имя выхода ONNX с метками классов. При проверке выполняется пробный прогноз на первых восьми строках.

Объект `provenance` включает записи `model`, `data`, `passport`, `policy`, `methods`. Для каждой укажите автора или поставщика в `author`, описание или идентификатор источника в `source`, дату получения с часовым поясом в `received_at` и версию в `version`. Для синтетических данных назовите генератор и обозначьте их происхождение.

## Регламент и каталог

В C1 задаются четыре метрики `accuracy`, `macro_f1`, `recall` и `confusion_matrix`. Порог ухудшения `threshold` лежит в интервале [0,05; 1), уровень значимости `alpha` — в (0; 0,05], размер группы `min_group` составляет не менее 50. Поле `search_fraction` равно 0,6. Поле `seed` содержит целое число от 0 до 2⁶³−1.

| Поле | Значение |
|---|---|
| `max_experiments` | Общий максимум, до 100 |
| `search_experiments` | База и поиск вместе, до 80 |
| `confirmation_experiments` | Максимум подтверждения, от 0 до 20 |
| `max_candidates` | Допустимое число кандидатов, от 0 до 20 |
| `memory_mb`, `disk_mb` | Положительные целые квоты в МиБ |
| `paid`, `money_limit` | При `paid: true` обязателен неотрицательный денежный предел |

Объект `seconds` содержит положительные целые лимиты. Верхние границы в секундах приведены в таблице.

| validation | preparation | baseline | search | confirmation | summary | total | report | export |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 300 | 120 | 300 | 2580 | 600 | 120 | 3600 | 300 | 600 |

C2 содержит непустой массив `methods`. У каждой записи есть уникальный `id`, строковая `version`, вид проверки `kind` (segment, noise или missing), объект параметров `parameters`, диапазоны `ranges`, описание предпосылок `prerequisites`, ограничений воздействия `impact_limits` и способа оценки `evaluation`. Числовому параметру соответствует диапазон с двумя включительными границами. Для метода без параметров оба объекта пусты.

```json
{
  "id": "measurement_noise", "version": "1", "kind": "noise",
  "parameters": {"amplitude": 0.05}, "ranges": {"amplitude": [0.0, 0.1]},
  "prerequisites": "Признак описывает измерение длины.",
  "impact_limits": "Соблюдать диапазон измерения и условие сохранения класса в паспорте.",
  "evaluation": "Сравнить ответы на тех же строках до и после изменения."
}
```

## Протокол проверки

Ответ содержит `valid`, список ошибок с полями `field` и `message`, сведения о размерах входов в `dimensions` и измерения в `resources`. Например, `data.length_mm` указывает на значение в таблице, а `passport.columns.2.type` — на тип третьей колонки в паспорте. При ошибке версия остаётся черновиком.

Протокол ресурсов хранит объём входов, свободный диск, доступную память с учётом ограничений cgroup, квоты, среду и оценку места под копию входов и подготовленные материалы. Для оценки памяти берутся измеренный пик процесса, удвоенный размер ONNX и две типизированные таблицы. Размер таблицы проверяется по мере чтения. После пробного прогноза фиксируется фактический пик процесса. Оценка характеризует предварительную проверку данного комплекта. Измерения последующих этапов собираются отдельно.
